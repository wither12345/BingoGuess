# 猜词 Bingo 使用说明

Minecraft 26.3 · Fabric · 服务端与客户端使用同一个 jar（`build/libs/guessbingo-0.1.0.jar`）。

## 玩法

每回合有一个隐藏的谜底，所有人共享猜词进度。

1. **猜词**：任何参赛玩家都可以猜，每次猜测的七列提示向全员公布。谜底未被猜中时，即使已经持有对应物品、站在对应地点，也不算完成。
2. **揭晓**：有人猜中后，谜底对全员公开，挑战开始生效。
3. **挑战**：第一个完成挑战的队伍得分，分值等于该题难度（1~5），然后进入下一回合。

一局由若干回合组成，按难度从易到难依次进行；同一局内不重置世界、物品栏和进度。

## 安装

| 位置 | 需要的模组 |
|---|---|
| 服务端 | `guessbingo-0.1.0.jar`、Fabric API、Yet Another Minecraft BINGO 2.15.1（26.3 版） |
| 客户端 | `guessbingo-0.1.0.jar`、Fabric API；装了 bingo 的客户端模组时会自动把它的棋盘让位给猜词面板 |

- Fabric Loader 需要 0.19 以上，Java 25。
- 客户端不装本模组也能玩：猜词用原版对话框，提示显示在聊天栏和动作栏，只是没有左上角面板。
- 不装 bingo 时进入“独立模式”：队伍取自原版 `/team`，用 `/gb start` 开局，结束后把玩家传回原位并清空物品栏、经验、效果和进度，但不会更换世界种子。

## 与 bingo 配合的开局流程

1. 第一次使用时在服务器上执行 `/bingo lobby` 并按提示确认，开启 bingo 的大厅模式。之后每局结束 bingo 都会删掉游戏世界、换种子重建，并把玩家送回大厅。
2. 玩家在大厅选队（bingo 自带的方式，或 `/join red`、`/join blue`）。
3. 管理员用 `/gb config count <难度> <数量>` 设定本局各难度的题数（每项 0~15）。
4. 用 bingo 的开始按钮或 `/bingo start` 开局。玩家进入新世界、倒计时结束后，猜词对局自动开始。
5. 全部回合结束后本模组公布比分，并让 bingo 结束这一局；之后的结算与重置都由 bingo 完成。

对局期间本模组会把 bingo 的结束条件临时改为“永不结束”，并把它的棋盘换成生存模式拿不到的物品，避免它自己播报任务或提前结束游戏。对局结束后结束条件会恢复原值。

每局结束后回到大厅的方式由 bingo 决定：玩家在结算界面投票进入下一轮，或管理员执行 `/bingo reset`。bingo 每局结束都会清空队伍，下一局要重新选队。

## 指令

所有玩家：

| 指令 | 作用 |
|---|---|
| 按 `G`（快捷操作键） | 打开猜词窗口：提交猜测、查询、历史记录、当前状态、玩法说明 |
| `/guess <名称>` | 提交猜测；名称不完整时会列出候选 |
| `/gb` | 当前回合、比分和最近的猜测 |
| `/gb history` | 本回合全部猜测 |
| `/gb search <关键词>` | 查询包含关键词的名称 |
| `/gb rules` | 玩法说明 |
| `/gb vote yes` / `/gb vote no` | 对跳过投票表态 |

管理员（权限等级 2 以上）：

| 指令 | 作用 |
|---|---|
| `/gb config` | 查看当前设置和各难度可用谜底数 |
| `/gb config count <难度 1-5> <数量 0-15>` | 设定某难度的题数 |
| `/gb config weight <类型> <权重>` | 设定某类型被抽中的权重，0 表示不出该类型 |
| `/gb config votetime <秒>` | 跳过投票的时限，默认 60 秒 |
| `/gb config hudrows <行数>` | 面板显示最近多少次猜测，默认 8 |
| `/gb config difficulty <难度> <名称>` | 修改某个谜底的难度 |
| `/gb config disable <名称>` / `enable <名称>` | 禁止或恢复某个词作为谜底 |
| `/gb config reset <名称>` | 恢复该词的默认设置 |
| `/gb config entry <名称>` | 查看某个词的难度、挑战方式和状态 |
| `/gb voteskip` | 发起跳过本回合的投票，同意人数达到在线参赛人数的一半即跳过 |
| `/gb skip` | 直接跳过本回合 |
| `/gb stop` | 立刻结束本局并公布比分 |
| `/gb answer` | 私下查看当前谜底 |
| `/gb start` | 手动开局（独立模式，或 bingo 已在游戏中但猜词没有自动开始时） |
| `/gb reload` | 重新读取配置文件 |

## 挑战的判定方式

| 谜底类型 | 揭晓后要做什么 | 说明 |
|---|---|---|
| 物品、方块 | 获得它 | 氧化程度、是否涂蜡、陶片与盔甲纹饰的图案、旗帜图案、音乐唱片的曲目不作区分；颜色、加工形态（台阶、楼梯、磨制等）、木材种类要区分 |
| 药水、药箭 | 获得该效果的药水或药箭 | 强度、时长不限；饮用、喷溅、滞留三种互相等价；药箭与药水分开算 |
| 实体（生物） | 击杀它 | 必须在谜底揭晓之后击杀 |
| 实体（非生物） | 获得它的物品形式 | 船、运输船不分木材；坐垫按颜色区分 |
| 结构 | 到达该结构内部 | |
| 生物群系 | 到达该生物群系 | |
| 附魔 | 获得带该附魔的任意物品 | 附魔书、装备、武器、工具都算 |
| 状态效果 | 获得该效果 | 包括瞬间治疗这类瞬时效果 |
| 进度 | 达成该进度 | 揭晓前就已达成的也算 |

除击杀外，谜底揭晓的那一刻已经满足条件的队伍各得一次分，并立刻进入下一回合；否则第一个满足的队伍得分。

## 配置文件

`config/guessbingo.json`（服务端）：

| 字段 | 默认 | 含义 |
|---|---|---|
| `countsByDifficulty` | `[3,3,2,1,1]` | 难度 1~5 各出多少题 |
| `typeWeights` | 全部 1.0 | 各类型的抽取权重。先选类型，再在类型内等概率选词；类型的实际权重是这里的数值乘以该类型候选数的平方根，所以方块、物品出现得更多，但结构、状态效果这样的小类也会出现 |
| `recentAnswerMemory` | 60 | 记住最近多少个谜底并在选题时避开，0 表示不避重 |
| `voteSeconds` | 60 | 跳过投票时限 |
| `scanIntervalTicks` | 10 | 物品栏、位置等判定的检查间隔 |
| `hudRows` | 8 | 面板显示的猜测行数 |
| `actionBarHints` | true | 给没装客户端模组的玩家在动作栏显示回合状态 |
| `autoStartWithBingo` | true | bingo 开局后自动开始猜词 |
| `neutralizeBingoCard` | true | 对局期间替换 bingo 棋盘 |
| `overrides` | 空 | 逐条覆盖难度或禁用，由 `/gb config difficulty` 等指令写入 |

`config/guessbingo-client.json`（客户端）：`enabled`、`scale`（默认 0.6）、`x`、`y`、`maxWidthFraction`（面板最多占屏幕宽度的比例，默认 0.45）、`maxColumnWidth`、`hideBingoCard`。

## 词库

词库来自「猜词」数据包，已去除属性、指令、更新三类和被移除的内容。每个词条的难度、是否能作为谜底及原因见 [词库报告.md](词库报告.md)。

- 方块、物品、进度的难度优先采用 bingo 自带的分级表（D=1、C=2、B=3、A=4、S=5）；其余类型是默认判断，可用指令逐条修改。
- 生存模式拿不到、26.3 中不存在、或没有物品形式的词条仍然可以猜，但不会被选为谜底。

## 已实测与尚未实测

已在本机的 26.3 环境里实测通过：

- 服务端端到端测试（两名模拟玩家、红蓝两队）：未猜中时持有物品不算、揭晓时已持有立即得分、先完成者得分并进入下一回合、击杀（揭晓前的不算）、持续效果与瞬时效果、两队同处一个生物群系时各得一分、揭晓前已达成的进度、附魔书、药水（水瓶不算、喷溅型加强版算）、等同颜色变种、跳过投票、模拟重启后的存档恢复。
- 2004 个可出题的谜底在 26.3 服务器上全部能解析到真实的物品、生物、进度等。
- 与 bingo 2.15.1 的对接：队伍取自 bingo、bingo 开局后猜词自动开始、棋盘被替换、猜词结束后 bingo 随之结束并恢复原来的结束条件、管理员用 `/bingo end` 时猜词随之结束。
- 客户端：面板、聊天栏提示、揭晓标题、四个对话框；装有 bingo 客户端时，对局中它的棋盘不再画在左上角。
- **bingo 大厅模式的完整循环**：在本机启动真实的专用服务器（已开启大厅模式），由真实客户端连上去走完“选队 → `/bingo start` → 猜词自动开始 → `/gb stop` → bingo 结算 → `/bingo reset` → 第二局”。两次实测中两局的世界种子都不同（例如 7536096611942751269 与 4729584496590208405），重置后玩家回到大厅、第一局拿到的物品和进度被清空，第二局猜词照常自动开始。服务器日志见 [大厅模式实测-服务器日志.txt](大厅模式实测-服务器日志.txt)。

尚未实测：

- 多名真实玩家同时联机（实测时只有一名真实玩家；两队同时在线的规则是用模拟玩家验证的）。
- “到达结构”的判定：测试没有走到任何结构里。实现用的是原版判断“玩家是否在某结构内部”的同一个接口。

## 本机的测试服务器

`run/` 是实测时用的专用服务器目录，可以直接再次启动：

```bash
gradle runServer
```

- 只监听 `127.0.0.1:25599`，离线模式，不对外开放；玩家 `Player0` 是管理员。
- `run/eula.txt` 里的 `eula=true` 是按你的同意写入的。
- `run/config/yet-another-minecraft-bingo/config.json` 里开启了 bingo 的大厅模式。
- 想重跑整机测试，先启动上面的服务器，等它就绪后在另一个终端执行：

```bash
gradle runClientGameTest -PwithBingo -PlobbyServer=127.0.0.1:25599
```

## 已知情况

- bingo 的侧边栏在对局中仍会显示它自己的目标和计分（恒为 0）。可以在 bingo 的选项里关掉这些显示项，计时那一行仍然有用。
- 猜词结束时本模组是通过 `/bingo end` 让 bingo 结束的，所以 bingo 的结算界面会写“RCON 停止了游戏”，棋盘上显示的是用来占位的不可获得物品。
- 大厅里 bingo 原本会展示一张“预览棋盘”，它与猜词无关，本模组会把这项显示关掉（受 `neutralizeBingoCard` 控制）。
- 不开大厅模式时，bingo 2.15.1 在进入结算时会在服务器日志里记一条它自己的报错（生成纪念地图时的日期格式问题），与本模组无关，不影响流程；大厅模式下没有这条报错。
- “不祥旗帜”“磁石指针”目前只能猜、不会出题，因为它们和普通旗帜、指南针是同一个物品，只靠附加数据区分。
- 物品类判定每 10 刻扫描一次物品栏（含盔甲、副手和鼠标上的物品），不检查潜影盒和收纳袋内部。

## 自己构建与测试

需要 JDK 25 和 Gradle 9.1 以上。`gradle build` 会顺带运行单元测试和服务端的游戏内测试；只想打包时用 `gradle assemble`。

```bash
gradle build
```

```bash
gradle runGameTest
```

```bash
gradle runGameTest -PwithBingo
```

```bash
gradle runClientGameTest
```

- `runGameTest` 启动无界面的测试服务器，用两名模拟玩家把各条规则完整跑一遍；加 `-PwithBingo` 时改为验证与 bingo 的对接。
- `runClientGameTest` 启动真实的游戏窗口并截图，截图在 `build/run/clientGameTest/screenshots`。
- 词库由 `tools/export_datapack.mjs` 和 `tools/build_lexicon.mjs` 生成。
